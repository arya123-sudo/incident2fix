# RCA-002: Discount code "save10" silently applies no discount

**Incident ID:** INCIDENT-002
**Triage Report:** TRIAGE-002
**Date:** 2026-09-19
**Severity:** SEV-3
**Confidence:** High

---

## Verdict

`apply_discount()` passes the raw user-supplied `code` string directly to `DISCOUNT_CODES.get(code, 0)` without case-normalizing it; because `DISCOUNT_CODES` keys are stored in uppercase only, any mixed-case or lowercase variant (e.g. `"save10"`) silently returns the default `0`, causing the full subtotal to be returned with no discount applied.

---

## Defect Location

`demo-app/app/discounts.py:11`

---

## Mechanism

[`DISCOUNT_CODES`](demo-app/app/discounts.py:3) stores keys in uppercase (`"SAVE10"`, `"WELCOME20"`). [`apply_discount()`](demo-app/app/discounts.py:9) calls `DISCOUNT_CODES.get(code, 0)` where `code` is the caller's raw input — never normalized. Python's `dict.get()` is case-sensitive, so `"save10"` does not match `"SAVE10"`, the default `0` is returned, and the expression `subtotal * (1 - 0)` evaluates to the full subtotal unchanged. No error or warning is raised, making the failure entirely silent to both the caller and any monitoring.

---

## Evidence

```python
# demo-app/app/discounts.py  (lines 3–11)
DISCOUNT_CODES: dict[str, float] = {
    "SAVE10": 0.10,
    "WELCOME20": 0.20,
}

def apply_discount(code: str | None, subtotal: float) -> float:
    """Apply a discount code to a subtotal. Unknown codes are ignored."""
    return subtotal * (1 - DISCOUNT_CODES.get(code, 0))   # ← no normalization before lookup
```

Execution trace for `apply_discount("save10", 100.0)`:
- `DISCOUNT_CODES.get("save10", 0)` → `0`  (key not found; "save10" ≠ "SAVE10")
- `100.0 * (1 - 0)` → `100.0`  (no discount applied)
